Moving down the rail

Closes on a receipt, not an empty screen.
The common case is that nobody is watching
The operator scans while the phone is in a pocket — BookingsFragmentNew already says so, which is why its ad-transition baseline is persisted rather than in-memory. So the choreography above is the rare case. When the change is discovered on a cold open, do not replay it: render the new state at once and draw only the rail segment, 500 ms, so the eye is led from where it was to where it is. Never fake the old state to animate away from it.
An interstitial may land first
On a detected transition the tab hands off to AdMobManager before it re-renders. If an ad shows, the live choreography is gone — the user comes back to a fresh screen. Treat the two as exclusive: run the full sequence only when the push arrives with the tab in front and no ad queued; otherwise fall back to the rail draw on arrival.
Checkout closes on a receipt
Today a checked-out booking simply vanishes from the tab, which is an odd way to end a transaction you paid for. The last frame proposes holding it as a completed card — time parked, amount — until the tab is next opened, then falling back to the empty state. That is new behaviour, not a restyle, so it is a call for you rather than an assumption.
